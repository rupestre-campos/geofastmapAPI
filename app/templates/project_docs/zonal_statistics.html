Zonal statistics (raster × feature)

Compute summary statistics of a registered raster (or STAC asset) inside a polygon / multipolygon feature. Zone geometry is loaded from the database by feature id and sent to Titiler POST /cog/statistics or POST /stac/statistics.

What we want

  • Zone: a feature geometry already in the API (vector collection item), or inline GeoJSON.
  • Raster: a local COG item (collection_type=raster) or a STAC item asset.
  • Stats: min, max, mean, count, std (and optional percentiles).
  • Optional categorical: unique pixel values and their counts (land cover, classes).
Important: a raster item’s own geometry is only its footprint. Zonal stats need a separate zone feature (or GeoJSON body) plus a raster source. Do not use the raster feature id as the zone unless you intentionally want whole-raster stats.

Building blocks already in GeoFastMap

  • Feature geometry: GET /collections/{collection_id}/items/{feature_id} → GeoJSON Feature (features_crud.get_feature + geometry_to_geojson).
  • Local COG: stored at {RASTER_STORAGE_PATH}/{collection_id}/{feature_id}.tif; exposed to Titiler via file:// or /internal/.../cog?token=….
  • Point sample: GET …/rasters/point, mosaic/STAC …/titiler/point/{lon},{lat} — same Titiler HTTP stack (client, retry, gate).
  • Full-raster statistics (no zone): STAC …/titiler/suggest-rescale already calls Titiler GET /cog/statistics or GET /stac/statistics for percentiles only.
  • Auth pattern to copy: coverage / items routes (can_see_collection), not the open /rasters/tiles|point routes.

Titiler capability (the right lever)

Titiler (rio-tiler) already supports zonal stats via POST (not GET). Geometry goes in the JSON body; the raster is identified by query url.

  • POST {TITILER_INTERNAL_URL}/cog/statistics?url=<cog>&bidx=1&… — local / single COG.
  • POST {TITILER_INTERNAL_URL}/stac/statistics?url=<item>&assets=<key>&… — STAC item assets.
  • Body: GeoJSON Feature or FeatureCollection (EPSG:4326 by default; override with coord_crs).
  • Default band stats include min / max / mean / count / std / histogram / percentiles.
  • categorical=true (and optional c= category values) returns per-class counts — use this for unique values.
  • max_size / width / height control rasterization resolution (trade accuracy vs latency).
  • nodata, expression, resampling mirror tile/point options.

MosaicJSON Titiler routes do not expose the same POST statistics endpoint. For a whole raster collection mosaic, either pick one item COG, or add a dedicated mosaic path later (in-process or custom).

OGC API patterns (how this maps)

  • OGC API - Features: resolve the zone (/collections/…/items/…). Already implemented.
  • OGC API - Coverages: we already expose lightweight “coverages” as download + tiles under /collections/{id}/coverages/{feature_id}. Statistics is a natural derived operation on that resource, but full OGC Coverages “range subsetting by polygon” is not standardized the same way as Features CRUD.
  • OGC API - Processes: best formal fit for “compute X from inputs A and B” and for large / long-running jobs (202 + /jobs/{id}), matching existing vector processes. Prefer Processes when polygons are huge or categorical unique-value scans are expensive.
  • Practical GeoFastMap split (same as tiles vs jobs): sync Titiler proxy for interactive UI; optional process later for batch / heavy work.

Public API (sync, Titiler-backed)

Implemented. Auth follows coverage/items patterns (can_see_collection on zone and raster).

1) Local raster item × zone (by feature ids)

GET /collections/{raster_collection_id}/coverages/{raster_feature_id}/statistics
  ?zone_collection_id=parcels
  &zone_feature_id=123
  &bidx=1
  &categorical=false
  &max_size=1024
  &nodata=-9999
  • API loads the zone GeoJSON from Postgres and POSTs it to Titiler /cog/statistics.
  • COG URL uses internal HTTP fetch when configured, else file://.
  • Extra query params (bidx, nodata, max_size, p, expression, …) are forwarded to Titiler.
  • Auth: can_see_collection on both raster and zone collections.

2) STAC item × zone

GET /stac/catalogs/{catalog_id}/collections/{collection_id}/items/{item_id}/titiler/statistics
  ?zone_collection_id=parcels
  &zone_feature_id=123
  &asset=B04
# or repeated assets=… (+ asset_as_band=true for multi-asset RGB)
  &categorical=true
  • Single asset → Titiler /cog/statistics with asset HTTPS href (SSRF rules already in STAC client).
  • Repeated assets → Titiler /stac/statistics with item self URL + assets=.
  • STAC access uses the same session / public-tile-grant rules as other Titiler STAC routes; the zone collection still requires view permission.

3) Zone-centric convenience

GET /collections/{zone_collection_id}/items/{zone_feature_id}/raster-statistics
  ?raster_collection_id=dem&raster_feature_id=abc
# or
  ?catalog_id=…&stac_collection_id=…&stac_item_id=…&asset=B04

Same Titiler call; useful when the map selection is the vector feature and the raster/STAC source is chosen separately.

Response shape

Returns a GeoJSON Feature with normalized band stats under properties.statistics, plus raster / zone metadata. 

{
  "type": "Feature",
  "geometry": { "…zone…" },
  "properties": {
    "raster": {
      "collection_id": "dem",
      "feature_id": "abc",
      "bidx": [1]
    },
    "zone": {
      "collection_id": "parcels",
      "feature_id": "123"
    },
    "statistics": {
      "b1": {
        "min": 12.0,
        "max": 880.5,
        "mean": 214.3,
        "count": 15234,
        "std": 91.2,
        "sum": null,
        "percentile_2": 30.1,
        "percentile_98": 710.0,
        "histogram": [ /* Titiler histogram */ ],
        "unique_values": [
          { "value": 1, "count": 400 },
          { "value": 2, "count": 1200 }
        ]
      }
    }
  }
}
  • unique_values only when categorical=true (derived from Titiler categorical / histogram output).
  • Multi-band → one entry per band (b1, b2, …) or per asset name for STAC multi-asset.
  • Empty intersection / all nodata → count: 0 and null aggregates (document clearly; do not 500).

Future: OGC process (async)

POST /processes/zonal-statistics/execution
{
  "inputs": {
    "raster": { "type": "reference", "collection_id": "dem", "feature_id": "abc" },
    "zone":   { "type": "reference", "collection_id": "parcels", "feature_id": "123" },
    "categorical": false,
    "bidx": [1],
    "max_size": 2048
  }
}
→ 202 { "jobID": "…", "status_url": "/jobs/…" }

Same input reference style as existing vector processes. Worker calls Titiler (or in-process rio_tiler on shared storage) and stores the JSON result on the job. Use when sync timeouts become common.

Implementation

  • app/services/zonal_statistics.py — zone load, COG URL, Titiler POST, response normalize.
  • Routes: titiler_proxy.py (local coverage), stac_items.py (STAC), items.py (zone-centric).
  • Tests: tests/test_zonal_statistics.py.

Limits & footguns

  • Resolution: default max_size undersamples large zones — document and allow override.
  • Timeouts: zonal POST is heavier than point; raise Titiler read timeout and/or force async process.
  • Unique values: catastrophic on float continuous rasters — only enable categorical for integer / classified data; optionally cap distinct values.
  • CRS: features are EPSG:4326 in API; pass coord_crs=epsg:4326 explicitly to Titiler.
  • Permissions: check both collections; STAC follows existing catalog/item grant rules.
  • SSRF: STAC assets must remain HTTPS + host allow rules.
  • Mosaics: not in v1 — pick one COG or add later.

Env vars (existing)

  • TITILER_INTERNAL_URL — required.
  • TITILER_INTERNAL_SECRET + RASTER_INTERNAL_FETCH_BASE_URL — preferred COG URL for Titiler.
  • RASTER_STORAGE_PATH — local COG root (file:// fallback when Titiler shares the volume).
  • Titiler HTTP timeouts / concurrency / retry settings — reuse; consider longer read timeout for statistics.
