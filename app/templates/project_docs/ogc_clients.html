QGIS, ArcGIS Pro & OGC API Features

GeoFastMap exposes an OGC API – Features–compatible API. Desktop GIS tools can connect to the same URLs as the browser, using the service root below. Visibility of collections follows Auth & permissions (public / logged / private).

Which URL to use

Point the client at the API base URL (the site root for this deployment). The server responds with the OGC landing document (JSON) and links to /collections, conformance, etc.

  • This deployment (example): {{ base }}/
  • Collections list (same API): {{ base }}/collections

Use https:// in production. If your hostname is behind a reverse proxy or tunnel, use the public URL clients will reach (not an internal Docker name).

Anonymous (no login)

Connect without username or password. You will only see collections whose visibility is public (and any other rules your server applies to anonymous users).

Service URL for GIS clients:
{{ base }}/

With username and password (your private & shared collections)

GeoFastMap accepts HTTP Basic authentication for API and GIS clients (same users as the web login). After you authenticate, the API can return private collections you own or that are shared with you, plus logged collections (any signed-in user), and public ones.

Service URL (unchanged): {{ base }}/
Authentication: Basic / HTTP Basic — enter your username and password in the connection dialog (not in the URL path).

Do not embed passwords in shared project files if others should not access your account; use a shared public collection or a dedicated viewer account when appropriate.

QGIS (3.16+)

  1. Open Data Source Manager (Ctrl+L) or the Browser panel.
  2. Choose Vector (or look for OGC API – Features under the browser, depending on version).
  3. Set the connection type to OGC API – Features if shown.
  4. URL / Service URL: {{ base }}/ (same as anonymous).
  5. Authentication: leave empty for anonymous; for your collections, open Authentication / credentials and choose Basic with your username and password.
  6. Connect and pick a collection (layer) to add.

Menu names vary slightly by QGIS version; search the help for “OGC API Features” if the entry moved.

ArcGIS Pro

  1. On the Map tab, use Add Data and look for OGC API – Features / Data from Path (wording depends on version).
  2. Server URL / Service URL: {{ base }}/
  3. If prompted for security, choose HTTP Basic (or “Username and password”) and enter your GeoFastMap credentials to see non-public collections.
  4. Select the collection(s) to add to the map.

Ensure your ArcGIS Pro version supports OGC API – Features; older builds may only support WFS 2.x.

Vector tiles (MVT): static and dynamic

GeoFastMap can also serve collections as vector tiles (Mapbox Vector Tiles / MVT). Some desktop GIS clients (including QGIS) can add MVT layers directly. Vector tiles are usually much faster for browsing large layers than fetching full GeoJSON features. See Tiles (static & dynamic) for background and trade-offs.

TileJSON URL (recommended)

Each collection exposes a TileJSON document at:

{{ base }}/collections/<collection_id>/tiles
  • When static tiles exist, TileJSON lists static first, then dynamic.
  • The TileJSON vector_layers[0].id is the source-layer name clients must use.

Direct tile URLs (Z/X/Y templates)

If your GIS client does not accept TileJSON, you can also use direct MVT templates:

  • Static tiles (prebuilt): {{ base }}/collections/<collection_id>/tiles/static/{z}/{x}/{y}.pbf
  • Dynamic tiles (from PostGIS): {{ base }}/collections/<collection_id>/tiles/dynamic/{z}/{x}/{y}.pbf

Static tiles require a build job first (UI: /collections/<id>/tiles/build?f=html). If static tiles are not built yet, the static endpoint returns 404.

QGIS: adding an MVT layer

  1. Open Data Source Manager → Vector Tiles.
  2. Use New and add either the TileJSON URL (/collections/<id>/tiles) or a direct URL template.
  3. If the collection is not public, set authentication (Basic) for the same host so tile requests include your credentials.
  4. Add the layer. If prompted for a layer name/source-layer, use the id from TileJSON: vector_layers[0].id.

Troubleshooting

  • Empty list or only some layers: check collection visibility and whether you used Basic auth for private data.
  • Certificate / HTTPS errors: fix the certificate or use a trusted URL on your network.
  • 401 / access denied: wrong password, or account not allowed to see that collection (see Auth & permissions).
  • MVT layer shows but has no features: verify the client is using the correct source-layer name from TileJSON (vector_layers[0].id).
  • Static tiles 404: build static tiles first at /collections/<id>/tiles/build?f=html (or use dynamic tiles).
