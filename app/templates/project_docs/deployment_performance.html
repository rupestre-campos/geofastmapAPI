Deployment & performance

This section focuses on practical knobs: what to scale, what to cache, and how to avoid common performance pitfalls.

For exposing the API from home with a domain and Cloudflare Tunnel (HTTPS without opening router ports, free-tier–friendly costs), see Deploy from home (Cloudflare).

For advanced multi-machine deployment on owned hardware (lab notes: primary host, optional small worker machines, Pi tunnel—work in progress), see Advanced setup (multi-machine).

Recommended production shape

  • API: FastAPI behind a reverse proxy.
  • DB: Postgres/PostGIS with adequate RAM and SSD storage.
  • Redis: enabled for queues and job metadata.
  • Workers: separate processes for bulk import and tile builds.

What to scale

  • DB CPU/RAM: dynamic tiles and complex queries are DB-heavy.
  • Worker CPU: tile builds and bulk imports are compute-heavy.
  • I/O: static tiles are file reads; fast storage helps.

Performance best practices

  • Prefer static tiles for large datasets and public browsing.
  • Keep tile properties small (exclude large fields).
  • Enforce sane limits for expensive searches (e.g., min length for full-text search).
  • Use partitioning and indexes for predictable query performance.

Large bulk uploads

Bulk import uses POST /collections/{id}/items/bulk with multipart/form-data. A 413 means something in front of uvicorn rejected the body; plain Docker Compose + uvicorn does not impose a small HTTP body limit by itself.

Cloudflare (including Cloudflare Tunnel)

Traffic to your public hostname goes through Cloudflare’s network before it reaches cloudflared on your machine. Cloudflare enforces a maximum upload size per request (typically 100 MB on Free and Pro, 200 MB on Business, higher on Enterprise—see Cloudflare’s Error 413 documentation). A multi‑gigabyte file cannot be uploaded through that path on a typical plan; changing nginx or Docker on the host does not raise Cloudflare’s limit.

Practical options:

  • Run bulk import on the same machine as Docker: open http://localhost:8000/… (or your LAN IP) so the browser talks to uvicorn without going through Cloudflare.
  • Split the dataset into several files under the limit and import with Append each time.
  • Use a VPN or other private path to your home IP that does not pass uploads through Cloudflare’s HTTP edge.
  • Enterprise / higher limits only if your Cloudflare contract allows larger uploads.

Client-side “chunking” only helps after the API supports multi-part upload sessions; see Collections & items → Large files, Cloudflare, and chunked browser uploads.

nginx (or similar) on your own server

If you terminate TLS or proxy in front of the API, nginx’s default client_max_body_size is 1 m, which also returns 413. Raise it and timeouts; see deploy/nginx-bulk-upload.conf.example in the repo.
