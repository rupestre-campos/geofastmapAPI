Deployment & performance

This section focuses on practical knobs: what to scale, what to cache, and how to avoid common performance pitfalls.

Recommended production shape

  • API: FastAPI behind a reverse proxy.
  • DB: Postgres/PostGIS with adequate RAM and SSD storage.
  • Redis: enabled for queues and job metadata.
  • Workers: separate processes for bulk import and tile builds.

What to scale

  • DB CPU/RAM: dynamic tiles and complex queries are DB-heavy.
  • Worker CPU: tile builds and bulk imports are compute-heavy.
  • I/O: static tiles are file reads; fast storage helps.

Performance best practices

  • Prefer static tiles for large datasets and public browsing.
  • Keep tile properties small (exclude large fields).
  • Enforce sane limits for expensive searches (e.g., min length for full-text search).
  • Use partitioning and indexes for predictable query performance.
