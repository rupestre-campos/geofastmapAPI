Vector tiles: static vs dynamic

GeoFastMap supports two ways to serve MapLibre-compatible vector tiles: static tiles (prebuilt, fast) and dynamic tiles (computed on demand, flexible).

Static tiles (prebuilt)

  • What: a tile file is generated for a collection and served repeatedly.
  • When to use: large datasets, repeated access, production “browse” use cases.
  • How it’s built: a background job runs the tile builder with your chosen options (zoom levels, simplification strategy, attribute selection, etc.).
  • Where configured: the “Build static tiles” page for a collection (/collections/<id>/tiles/build?f=html).
  • What you get: consistent performance for map browsing and style-editor previews (tiles are just read from disk).

Dynamic tiles (query-time)

  • What: tiles are generated per request from Postgres queries.
  • When to use: ad-hoc filtering, interactive exploration, small-to-medium datasets, or when you cannot prebuild tiles.
  • Trade-offs: more CPU/DB load; performance depends heavily on indexes, filter selectivity, and request patterns.

How requests flow

  • Static: MapLibre requests {z}/{x}/{y} → GeoFastMap reads from the prebuilt tiles file → returns bytes.
  • Dynamic: MapLibre requests {z}/{x}/{y} (+ query params) → GeoFastMap builds a SQL query → encodes features into MVT → returns bytes.

Tile build options (what they mean)

  • Min/Max zoom: controls tile resolution. Higher max zoom increases output size and build time.
  • Attributes include/exclude: controlling properties reduces tile size and improves render performance.
  • Simplification: reduces geometry complexity at low zooms; improves speed and size but can reduce precision.

Practical guidance

  • Start with conservative zooms (e.g. max 12–14) and only increase if needed.
  • Prefer excluding large or low-value attributes (long strings, verbose JSON blobs) from tiles.
  • For polygons: simplification can greatly reduce size at low zooms without changing user-visible results much.

Limitations & operational notes

  • Static tiles must be rebuilt when data changes to reflect updates.
  • Dynamic tiles should avoid expensive full-text queries for very short strings (we enforce a minimum length where needed).
  • Very large collections may require tuning database and worker resources.
