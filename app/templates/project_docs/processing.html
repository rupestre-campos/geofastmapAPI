Processing (OGC API - Processes)

Processing endpoints run geometry operations (intersection, erase, buffer, explode, make valid, union, measure, etc.) as asynchronous jobs. Results are written into collections (new or existing, depending on the operation).

How it works

  • The UI submits a process request with input collection ids (and sometimes feature ids).
  • A job is created and enqueued.
  • The worker performs DB-side geometry work and writes results.
  • Optionally, a static tile build can be queued for the result collection.

Common limitations

  • Large geometry operations can be expensive; use bounding boxes and filtering when possible.
  • Result collections can be big—consider tile build settings and attribute selection.
