Jobs & workers

Long-running tasks (bulk import, tile building, processing) run as jobs. Jobs are visible to the owner; admins can see all.

Job lifecycle

  • pending → running → completed (or failed)
  • Some jobs can be cancelled (e.g. pending tile builds).

Job storage

  • GeoFastMap stores job metadata either in Redis or in-memory depending on configuration.
  • In production, Redis is recommended so job status survives process restarts.

Queues and storage

  • Redis is used for worker queues and durable job metadata in production-like setups.
  • A memory queue may be used in development (single process).

Ownership

  • Jobs created from UI actions should carry the user’s owner_id.
  • Legacy jobs without an owner are treated as admin-only for safety.

Common issues

  • “Job not found” for a logged-in user: typically means the job has no owner_id or belongs to another user.
  • Jobs stuck in pending: indicates the corresponding worker is down or not consuming its queue.
  • Tile builds re-queued: safety logic may allow re-queue if a build appears stuck for too long.
